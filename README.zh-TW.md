AI 寫出來的東西有一種固定的味道，你一定讀過。意義硬拉高、形容詞三個一串、結尾收得漂漂亮亮卻什麼也沒講。市面上那些「去 AI 化」工具多半只做一件事：把這層味道刮掉，還你一段乾淨、但也沒有人味的文字。Rewild 做的是另一件事——把 AI 模式拿掉，再把你自己的聲音放回去：立場、節奏、不那麼平整的地方。它不會替你編事實，也不會給你套一個原本不存在的人設。

**269 條分語言的模式。五個技能。一支會讀你原文、不是只讀你改稿的檢查腳本。**

## 到底有沒有用

被量的是兩件事，回答的問題不一樣。

**這一版比上一版好嗎？** 評審拿到同一篇原文的兩份改寫稿，二選一，不准打平——這樣測試就不會像打勾清單那樣做著做著就滿分。五篇輸入，三位互不通氣的評審，沒有人知道哪一份出自哪套系統。

| | English | 中文 |
|---|---|---|
| 被判定優於上一版 | **10 / 12（83%）** | **9 / 12（75%）** |
| 讀起來比較不像機器寫的 | 是 | 是 |

中文這個數字是跑了三輪才拿到的：6/12、7/12，最後 9/12。每一輪都修掉一個真的缺陷。舉一個例子。中文技能裡有四個地方把句末語氣詞當成必須湊到的指標，模型於是在一封內部信裡硬塞了一個「啊」。三位評審全都圈了同一句。現在語氣詞是拿來診斷的，不是拿來達標的。

**香港的稿讀起來像香港，台灣的稿讀起來像台灣嗎？** 這是繁體技能真正在主張的事，所以直接測。三篇來源、三個組（`hk`、`tw`，外加一個只說「請用繁體中文、寫得像人寫的」的對照組），九份輸出各自蓋成一個單字母，三位評審——一位中立，一位以香港讀者的身分讀，一位以台灣讀者的身分讀。

| | 結果 |
|---|---|
| 技能輸出的地區歸屬 | **18 / 18** |
| 自己地區的自然度排序 | **6 / 6** |

每一位評審都把每一篇放對了邊，四輪累計 50/50。第二輪還補上第一輪漏掉的難題：一篇台灣新聞稿丟給香港技能改，一篇香港內部信丟給台灣技能改。沒有一篇被誤判成大陸的寫法。這個結果之所以有意義，是因為對照組寫得並不差——評審說它通順，而且單看詞彙大多是台灣的，因為沒人指導的模型本來就會自己伸手去拿「專案」和「使用者」。它做不到的只有一件事：選邊。*「詞彙查對了台灣，但語感與收尾仍是大陸的。」* 有一位評審把它三篇裡的兩篇判去了大陸。沒有地區的繁體中文是真實存在的產物，它只是不屬於任何人。

這一輪也挖出三個缺陷，其中一個是任何工具都抓不到的：香港新聞稿裡的「處理到」是粵語語法穿著標準漢字，逐字比對的腳本看不見。三個都寫在 [`benchmarks/`](benchmarks/) 裡。

**一篇稿到底能改到多好？** 上面那兩項都是比較——這一組對那一組、落在哪一邊。等到兩組都對了，它們就再也說不出東西。所以還有第三種量法，而且沒有天花板：把一篇散文交給一位評審，提示詞整段用繁體中文寫，角色設定是做了三十年的報紙副刊總編輯，請它打 1 到 10 分，並且把每一句讀起來像機器寫的都引出來。照著改，再交一次。

| | 香港 | 台灣 |
|---|---|---|
| 初稿 | 5 | 5 |
| 七輪，每輪換一位評審 | 5 → 8 | 5 → 8 |
| 結構重寫，固定同一位總編輯 | 7 → 8 → 9 | 8 → 9 |
| 終審 | **10 — 落版，唔使再改** | **10 — 簽字發稿** |

**詞彙會飽和，結構不會。** 從第二輪開始，兩邊的總編輯都挑不出一個字的毛病——「字是台灣人的字，結構是機器的結構」。8 分到 10 分之間差的全是手藝分佈得太平均：每一段都收得漂亮、沒有半句廢話、數字每一段配一個、墊詞撒得太勻、結尾跟主旨一比一對應。這一條現在是五個模式庫共同的一條模式（見〈為什麼有用〉）。有件事要先講清楚，跟地區測試那邊一樣：這些評審是語言模型，不是真人讀者。流程和完整的分數軌跡都放在 [`benchmarks/`](benchmarks/)。

**比一般的去 AI 工具好嗎？** 早先一次跑分是 30/30 對典型 24 條規則工具的 24/30，中文那邊是 30/30 對 20/30。這個數字請當成未經確認：原始輸出沒留下來，而且那次跑分早於下面講的那些腳本修正。測試用的東西都在 [`benchmarks/`](benchmarks/)——輸入、評分標準、對照組提示詞、盲評流程，你可以自己跑一遍，然後告訴我我錯了。

> **輸入：** 在數位轉型的浪潮中，本公司始終堅持以創新為核心，打造全方位、一站式的智慧解決方案，為客戶帶來前所未有的使用體驗。
>
> **一般工具：** 我們做了一套系統，幫客戶省下處理雜事的時間。上線之後的回饋還不錯，多數使用者說流程比以前順。
>
> **Rewild：** 我們做的東西確實幫客戶省下時間，這句話站得住。虛的是「前所未有」那四個字。

一般工具把大話換成小話，Rewild 直接把它點出來。

## 為什麼有用

大多數去 AI 工具就二十來條通用規則：刪掉「此外」、句子長短調一調、收工。表面的東西處理完就沒有了。Rewild 多做的功夫集中在六個地方。

**每種語言一套模式，不是一套規則通吃。** 英文 AI 愛用 testament 和 landscape，破折號一個接一個。中文 AI 不放語氣詞，四字成語一串接一串。德文 AI 迴避 Modalpartikeln，還會把複合詞拆開寫。每種語言有自己的模式庫，材料來自學術研究和真實的偵測資料；繁體中文再往下分到「地區」，理由寫在後面那一節。

**詞彙全對了還是會露餡。** 每個字都挑對了，一篇第一人稱的散文照樣讀起來像機器做的，因為手藝分佈得太平均：每一段都用一句短而乾的話收尾、每一個丟出來的細節後面都有回收、具體的東西一段配一個、墊詞撒得均勻而不是擠在一處、結尾那個畫面跟主旨一比一對上。沒有一處寫得差，這正是證據。把一個漂亮的結尾換成另一個更漂亮的結尾不算修——換的是衣服，不是人。真正的修法是願意讓某一段收得平、願意讓某個細節丟了就丟了、除了一處之外全都寫得含糊。五個模式庫都帶著這一條，每一份 `SKILL.md` 也都帶著那道檢查：把每一段的最後一句抄出來，排成一直行，看那一行。

**日常口語的語域，不是只有新聞稿的語域。** 地區模式庫本來在公文、新聞和商業中文上很強，可是關於一個人怎麼講自己的手機，一條也沒有——而那才是大部分人真正拿來改的東西。現在補上了：

| 概念 | 台灣 | 香港 | 大陸 |
|---|---|---|---|
| calculator | 計算機 | 計數機 | 計算器 |
| 滑動作 | 滑手機 | 碌手機 | 刷手機 |
| to like | 按讚 | 讚好 | 點讚 |
| power bank | 行動電源 | 尿袋 | 充電寶 |

還有一組不是名詞而是動詞：台灣人說「賴我」，香港人說「WhatsApp 我」。把平台名拿來當動詞用，一句就把作者住在哪裡交代完了。

兩位母語審稿人把這些列逐條查證過，砍掉了好幾行：結帳、追蹤、動態、平板、截圖、限時動態、計算機——這幾個要嘛三地通用，要嘛台灣以外一樣這樣講，抓了就會誤殺台灣原生的文字。它們被列為不可入閘，而且加了回歸測試守住這個結論。把一個本來就正確的詞反向替換掉，等於把地區判斷變成語域錯誤，那比原本要修的問題還難看。

**防止矯枉過正。** 每一篇都用同樣三招去 AI 味——短句連發、刻意的自我修正、每一節配一個反問——你只是造出另一套一樣好認的模板。Rewild 限制單篇的改動數量，而且換著用。

**忠實度，不只是文風。** 這是大部分工具完全跳過的一塊。一篇改寫可以一個人名一個數字都沒編，照樣說出原文沒說過的話。有四種走法：

- 原文把判斷掛在別人名下，改寫把出處刪了，判斷留著
- 原文只是在描述，改寫變成了承諾
- 原文寫「受到影響」，改寫寫成「全都不能用」
- 原文交代了一個原因，改寫順手排除掉其他可能

前三種，自帶的腳本拿你的改稿跟原文一比就查得出來。第四種查不了，只能靠寫的人，模式庫裡也是這樣寫的。

**不編造，包括那些聽起來很謙虛的話。** 輸出裡的每一個細節都必須原文已經有。這條規則以前有個漏洞：舊版本告訴模型，把沒有來源的吹捧刪掉之後，可以補一句誠實克制的自評，模型就照做了。一篇行銷稿長出了原文沒有的免責聲明。一份改版公告讓公司認了一個自己從來沒提過的短處。謙虛版的編造，還是編造。

## 怎麼改

香港和台灣多一道前置步驟：先對全文做一次地區掃描，查對面地區的用詞、譯名、大陸套語和字形錯誤。它排在最前面，因為地區問題跟段落乾不乾淨完全無關——一段一點 AI 味都沒有的文字，照樣可以整段站在海峽的另一邊。

然後每一段在動手之前先分類。重度 AI 味的文字逐句修，只會把骨架擦亮，架子還立在那裡，所以工作分三條路：

- **本來就像人寫的？** 不動。改過頭是這類工具最常見的翻車方式，乾淨的段落頂多修一小處。
- **有零星痕跡？** 對照模式庫原地改掉。
- **通篇 AI 味？** 重說一遍。把事實記下來，原文放到旁邊，用同樣的語域重新寫，寫完再逐條核對每個細節都來自原文。

重說改的是措辭，不是順序。一篇散文自己說了「最重要的一課」是哪一件，你把它挪到結尾，前面所有鋪墊就落空了。

正式文體完全不走重說這條路。新聞稿、公告、公文只刪只壓——書面骨架本身就是語域，重說很容易滑進聊天腔。

交付前跑兩道檢查。一位不記得原文的審稿人盲看改寫稿，把還像 AI 的地方標出來。然後腳本量一遍模型自己看不見的統計痕跡，並且把改稿跟原文做比對。風格類警告是建議，忠實度類警告是硬傷。

## 繁體中文在這裡是兩種語言

看起來最省事的做法，是做一個繁體技能，加一個地區參數。這條路走不通，因為**兩地各自的正確用詞，正好落在對方的錯誤用詞裡。**

| | 香港 | 台灣 | 大陸 |
|---|---|---|---|
| software | 軟件 | 軟體 | 软件 |
| internet | 網絡 | 網路 | 网络 |
| smart | 智能 | 智慧 | 智能 |
| project | 項目 | 專案 | 项目 |
| Trump | 特朗普 | 川普 | 特朗普 |

看表格裡「網路」「智慧」「專案」「川普」那四列。香港欄填的東西，跟大陸欄是同一個詞，差別只在字體——換句話說，它們是**台灣技能必須清掉的大陸詞，同時是香港技能必須護住的香港詞。** 一份黑名單裝不下兩套相反的規則；而地區參數一旦沒填，模型就會取一個中間值，寫出來的正好是兩邊都不認的東西：文法沒錯的繁體中文，但不屬於任何人。

還有兩條分岔把結論釘死。譯名是這門語言裡最快的破綻，台灣讀者看到「歐巴馬」被寫成香港那個譯法，一句之內就知道稿子不是自己人寫的。另外香港有一條台灣根本沒有的語域軸：書面語對書面粵語（係／唔／嘅／咗），這條分支放進台灣技能裡純粹是死重量。

兩份模式庫都不是簡體版的翻譯。45 條簡體模式是一條一條過的：香港保留 29、改寫 15、刪 1；台灣保留 25、改寫 19、刪 1。然後各自再加 21 條簡體模式庫裡根本沒有的地區模式。兩份檔案裡有意義的段落分別是 191 段和 184 段，逐位元組相同的只有一段。其中有幾條「改寫」其實是**撤銷**，因為原規則會把當地正常的文字判成 AI 味：

- 香港刪掉「名詞化成癮」。作出／進行／予以 是香港書面中文最有辨識度的語域標記，一條去名詞化的規則，是最快把港味磨平的辦法。
- 台灣刪掉「功能詞失衡」。這條出自英文語料，它那句「把句子寫直」的處方，正好跟台灣天然更鬆的語域對著幹。
- 台灣的日語底層結構（「⋯的部分」「⋯性」「⋯感」）被標成母語成分並且受保護。一條按大陸語感調校的「去翻譯腔」規則會把它們全鏟掉，反而把文字推回大陸中性——正是這個技能存在的目的所要防的事。
- 香港的表情符號規則放寬了，因為香港機構的對外溝通（Facebook 專頁、WhatsApp 通知）本來就在用。

兩份模式庫最後都附一張表，列出每一條被撤銷的規則和理由，免得以後有人順手把它加回去。

## 怎麼安裝

1. 把你要用的那個語言的技能資料夾（`rewild/`、`rewild-zh/`、`rewild-hk/`、`rewild-tw/` 或 `rewild-de/`）整個複製到技能目錄，Claude Code 是 `~/.claude/skills/`。資料夾名稱和內容都別改：資料夾名稱跟技能自己的 `name:` 欄位是對應的，`references/` 模式庫和 `scripts/` 檢查腳本也要一起帶走。
2. 在別的 LLM 裡，把 `SKILL.md` 當系統提示詞貼進去，`references/patterns.md` 放在旁邊讓模型按需讀取。
3. 說「rewild 一下」，然後把你的文字貼上。

## 自帶的檢查腳本

每個技能資料夾都帶一支 [`scripts/naturalness-check.py`](rewild-tw/scripts/naturalness-check.py)，Python 3，零相依。跑它是工作流程裡的必做步驟，不是加分項。

把原文和改稿一起傳進去，兩半的活它都幹：

```bash
python3 rewild-tw/scripts/naturalness-check.py 改稿.txt --source 原文.txt --lang tw
```

風格那一半量的是模式庫描述的東西：句長是否均勻、句子開頭是否重複、段落長短是否雷同、AI 高頻詞、連接詞密度、標點問題。忠實度那一半把兩份文字對比，抓出改稿裡多出來的人名和數字、替原文做的承諾、被搶過來的判斷、被抬高的嚴重程度。中文這邊它會用結構去讀人名（機構、地名、職銜附近的標記），也會解析中文數字，因為一篇寫「三個星期」「凌晨兩點」的稿子一個半形數字都沒有，數字檢查等於跑在空氣上。有警告時退出碼是 1，乾淨時是 0，所以它也能直接當門禁用。

`--lang hk` 和 `--lang tw` 還多出第三半，而且正是前面那些風格檢查完全看不見的一半：對面地區的用詞、只有大陸才用的詞、對面的譯名、轉換後殘留的簡體字、地區字形標準，以及港文裡的「您」——粵語沒有這個字，一個就夠把稿子的來源定在大陸。

| 概念 | 台灣 | 香港 |
|---|---|---|
| 裡面 | 裡 | 裏 |
| 動貌助詞 | 著 | 着 |
| identity | 身分 | 身份 |

它還會查地區轉換最常漏掉的一樣東西：**套語**。把一份香港通函改成台灣的，能換的名詞只有四個，骨架原封不動：

| 換掉了 | 沒換掉 |
|---|---|
| 網絡、質素、數碼、人工智能 | 是次、謹將⋯通知如下、鳴謝、順頌業祺 |

中文沒有錯，骨頭是錯的。哪些套語算產地證據、哪些只是常用，是數出來的，不是憑感覺定的：

| 套語 | 在 820 萬字香港政府新聞稿中 | 判定 |
|---|---|---|
| 攜手合作 | 出現 74 次 | 是台灣的套語，但不是「這篇來自台灣」的證據，已從那項檢查排除 |

它還抓一類沒有任何風格檢查在看的缺陷：**簡繁一對多的轉換錯誤**。簡體轉繁體時，一個源字可能對應好幾個目標字，轉換器會挑錯：

| 錯 | 對 |
|---|---|
| 以后 | 以後 |
| 標准 | 標準 |
| 髮展 | 發展 |
| 聯系 | 聯繫 |

這些字串裡每一個字都是合法的繁體字，只有意思是錯的，所以校對根本看不出來。

地區類警告是硬傷，不是建議。風格類警告才是建議：有理由的警告好過沒道理的修改。

還有一個模式，專治每一項單篇檢查在結構上都看不見的失敗。一口氣改五篇相關的稿，它們會收斂——段數一樣、收尾的動作一樣、同一句話扛著同一個事實——可是每一篇單獨跑都是乾淨的：

```bash
python3 rewild-tw/scripts/naturalness-check.py --siblings 稿1.txt 稿2.txt 稿3.txt --lang tw
```

兩次獨立的基準測試都撞上這件事，兩次都只能靠人把成品並排讀一遍才發現。來源本來就重疊的時候，用詞撞在一起是正常的；撞在一起的是**形狀**，那就是同一個模板刷了好幾層漆。

再來一個，專治每一輪盲測都抓到、卻沒有任何檢查在看的失敗——一篇在地區、語域、忠實度上都乾淨，卻已經不是它自稱的那種文件了：

```bash
python3 rewild-tw/scripts/naturalness-check.py 改稿.txt --genre outage --lang tw
```

`release`、`outage`、`pressrelease`、`notice` 四種。它會報出缺了什麼，然後拒絕幫你把它補上：原文如果從來沒有日期或聯絡方式，補一個叫捏造，不叫修復。

有一件事它做不好，直說：拿它去跑模式庫，會滿螢幕警告，因為模式庫本來就在引用錯誤寫法當教學例子。它是給改寫稿用的。模式庫請改用 `--audit`。

有幾處是隨手實作容易做錯的。markdown 按正文讀，不按骨架讀——標題、程式碼區塊、表格行會跳過，列表項各算一句。比對不受排版影響，彎引號直引號一視同仁。詞彙比對跨詞形，所以 `streamline` 也會找到 `streamlined` 和 `streamlining`。縮寫不當句尾，`Dr. Chen shipped it at 4 p.m.` 不會被算成三句。

改完模式庫跑一次 `--audit`，它會拿腳本裡的詞表跟旁邊的模式庫對一遍，把模式庫寫了、腳本卻看不見的東西列出來：

```bash
python3 rewild/scripts/naturalness-check.py --audit --lang en
```

腳本歷史上出過的每一個 bug 都有回歸測試蓋住，現在是 146 條，從 30 條長上來的：

```bash
python3 tests/test_checker.py
```

## 結構設計

每個技能拆成兩個檔案外加一支腳本，這個拆法是有講究的。

`SKILL.md` 是操作手冊：什麼時候觸發、什麼不能動、不同文體怎麼校準、好的聲音長什麼樣。它每一次都要載入上下文，所以要精簡。

`references/patterns.md` 是診斷目錄：痕跡的完整清單，帶詞表、改寫前後對照和出處。模型按需讀取其中的章節，不必一開始就全部載入。

測試裡還跑出一個結果，老實說有點出乎意料：一條規則放在哪裡，跟它怎麼寫一樣重要。忠實度那幾條原本放在講「聲音」那一節的末尾，於是模型動筆前讀到的最後一段全是禁令。它寫得畏畏縮縮，盲測輸在 5/12。一個字都沒改，只是把同樣的文字挪進「寫完之後核對」那一節，結果變成 10/12。
